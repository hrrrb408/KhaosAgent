## Model action and budget

AgentHost asks for one JSON object with exactly ten keys. Shell actions carry argv, readScope and writeScope while six other fields remain empty. The prompt explicitly asks the model to write a Python source-editing script, put it in one argv string, and supply exact read and write scope. It uses Path.read_text, str.replace, an assertion that some content changed, and Path.write_text as the example. That assertion does not prove one match: Python replace changes every occurrence by default. The prompt itself also tells the model to inspect return codes, read bounded source and test output, and propose edits before rerunning a failed test. See [AgentHost prompt](https://github.com/hrrrb408/KhaosAgent/blob/23d00c762af04b20b46f818fc611bcd5db16a211/khaos/macos/AgentHost.swift#L108-L129).

The output validator requires the ten-key action shape and currently accepts text, shell, list, Plugin and evolution actions. For workspace actions, the Host turns shell or list into an AgentShellProposal. See [action validator](https://github.com/hrrrb408/KhaosAgent/blob/23d00c762af04b20b46f818fc611bcd5db16a211/khaos/macos/AgentHostActionOutput.swift#L114-L173) and [encoding](https://github.com/hrrrb408/KhaosAgent/blob/23d00c762af04b20b46f818fc611bcd5db16a211/khaos/macos/AgentHostActionOutput.swift#L357-L453).

Existing limits are eight reviewed calls/task, 30 seconds/call, 180 seconds/task, 4 KiB/result and 32 KiB/task. AgentHost history is bounded to 8 KiB; each source fragment is prompt-capped at 900 bytes; Launcher stream prefixes are capped at 1,400 bytes. The action grammar allows at most eight argv items even though the internal protocol validator allows more. A candidate edit must fit these limits without increasing them. Evidence: [history and prompt](https://github.com/hrrrb408/KhaosAgent/blob/23d00c762af04b20b46f818fc611bcd5db16a211/khaos/macos/AgentHost.swift#L82-L129), [protocol bounds](https://github.com/hrrrb408/KhaosAgent/blob/23d00c762af04b20b46f818fc611bcd5db16a211/khaos/macos/AgentHostProtocol.swift#L124-L153), and [Launcher stream cap](https://github.com/hrrrb408/KhaosAgent/blob/23d00c762af04b20b46f818fc611bcd5db16a211/khaos/macos/TrustedWorkspaceLauncherMain.swift#L2179-L2181).

The current model grammar also caps each `argument` at 1,024 grammar `char` units and each `path` at 128 units. The internal protocol separately caps each argv item at 4,096 UTF-8 bytes and each scope path at 128 bytes. Because a B request would be lowered into nested JSON strings, its model-facing text fields need their own conservative bounds, derived from the exact serialization; the protocol's 4 KiB item cap is not a 4 KiB source-text allowance. See [action grammar](https://github.com/hrrrb408/KhaosAgent/blob/23d00c762af04b20b46f818fc611bcd5db16a211/khaos/macos/AgentHost.swift#L158-L173) and [protocol byte limits](https://github.com/hrrrb408/KhaosAgent/blob/23d00c762af04b20b46f818fc611bcd5db16a211/khaos/macos/AgentHostProtocol.swift#L124-L153).

## Read, edit, test and approval path

- Discovery: model proposes list with a narrow directory read scope; Kernel returns immediate entries. Directory read scope covers descendant files, so it is broader than a file read.
- Source inspection: model proposes shell with exact file read scope and Python code that selects lines or searches identifiers. The result remains untrusted and bounded.
- Edit: model proposes another shell action, usually a Python command. The action's read and write scopes are separate.
- Test: model issues a later shell action whose read scope must include the test and local dependencies. Test output and return code are returned as untrusted observations.
- Progression: Launcher permits only one next proposal after each result while the call and byte budgets remain; every proposed operation receives separate user approval. A denial stops the task.
- Approval: Launcher displays the actual argv, readable paths, committable paths, and request digest. It does not show a semantic source diff. See [operation assembly](https://github.com/hrrrb408/KhaosAgent/blob/23d00c762af04b20b46f818fc611bcd5db16a211/khaos/macos/TrustedWorkspaceLauncherMain.swift#L1916-L1968), [approval display and denial](https://github.com/hrrrb408/KhaosAgent/blob/23d00c762af04b20b46f818fc611bcd5db16a211/khaos/macos/TrustedWorkspaceLauncherMain.swift#L2053-L2072), and [approved details](https://github.com/hrrrb408/KhaosAgent/blob/23d00c762af04b20b46f818fc611bcd5db16a211/khaos/macos/TrustedWorkspaceLauncherMain.swift#L2302-L2323).

The trusted Launcher serializes argv and scopes into a fixed Runner source that invokes process_exec and then workspace_commit. A normal nonzero command result still reaches the scoped commit frame. This is relevant to edit-failure semantics: an approved command may have an in-scope partial snapshot write even if the command exits nonzero. The source edit path must account for that; an edit abstraction cannot claim atomicity just because preconditions are validated first. See [agentRunnerSource](https://github.com/hrrrb408/KhaosAgent/blob/23d00c762af04b20b46f818fc611bcd5db16a211/khaos/macos/TrustedWorkspaceLauncherMain.swift#L2159-L2176).

## Trusted execution and changeset handling

The workspace.run wire request remains fixed to timeout, Runner source and digest, workspace_read_scope and workspace_write_scope. The trusted XPC decoder validates those exact fields at [KernelWorkspaceXPC.swift](https://github.com/hrrrb408/KhaosAgent/blob/23d00c762af04b20b46f818fc611bcd5db16a211/khaos/macos/KernelWorkspaceXPC.swift#L768-L788).

The current ABI gives process.exec a private snapshot, fixed cwd/environment/timeout/sandbox, and the retained read scope. A shell command can change the private snapshot, but the complete changeset is untrusted. Before live writeback the Kernel requires each added, modified or deleted entry to exactly match the trusted workspace_write_scope; any out-of-scope path rejects the complete changeset before the live mutation gate. Write scope is exact-entry based and does not authorize descendants. See [KERNEL_ABI scope and changeset contract](https://github.com/hrrrb408/KhaosAgent/blob/23d00c762af04b20b46f818fc611bcd5db16a211/docs/KERNEL_ABI.md#L208-L234) and [process.exec / workspace.commit](https://github.com/hrrrb408/KhaosAgent/blob/23d00c762af04b20b46f818fc611bcd5db16a211/docs/KERNEL_ABI.md#L354-L389).

Khaos does not promise multi-file rollback. Commit outcome can be uncertain after some live writes, so the recommended initial edit interface must remain single-file and must not claim all-or-nothing workspace transactions. The ABI states this explicitly at [multi-file commit limits](https://github.com/hrrrb408/KhaosAgent/blob/23d00c762af04b20b46f818fc611bcd5db16a211/docs/KERNEL_ABI.md#L461-L468).

## Finding

For the demonstrated one-file edit, the model currently performs several jobs that a deterministic adapter could own: Python source construction, literal quoting, exact uniqueness checks, and replacement-count validation. This is a concrete affordance cost visible in the prompt example, not a proven explanation for the M8.4 model outcomes. Localization, planning, context retention, test selection and model reasoning remain unresolved alternatives.
