# M8.4 preregistered protocol

The fixed order is A/a-01, C/c-01, C/c-02, A/a-02. At most four independent formal attempts are planned, two per group. Each requires new explicit remote-data authorization before transmission, followed by the Launcher's separate task-data decision and independent review of every tool operation. Prior M8 authorization does not apply. No automatic approvals, reruns, fallback, prompt changes, or added attempts are permitted.

Both groups derive from PR #31 head f5631de1b5ebb056af28bbd145757b6f76053154 with the same opt-in bounded observation implementation. A removes exactly the reviewed list/shell missing-text normalization block; C retains it. No other group-specific source change is permitted. Both products are built and signed independently before use. Trusted source/input maps, signed and unsigned executable digests, entitlements, build configuration, and signatures are compared. Code signatures, signing timestamps, and build-record identity differences are recorded separately.

The frozen task is runner-exception-classification. Prompt SHA-256 is 7a86c99de62538d4c514cb0f5fa1dd31d747701be60f03c12d4a2420736810a2; workspace baseline is 7b6af61b3925b28ef105ea521c49424344de04c5; hidden patch SHA-256 is 185ea8ada844d790c0d716b2d7d921c8c4e739b238baa5d1b7b325e6fc446e16. Input mismatch stops execution. Original manifest, grader, tests, gold patch, and task text remain unchanged. Hidden tests and reference material stay outside model workspaces and model input.

Both arms use bigmodel-coding-plan, glm-5.3, https://open.bigmodel.cn/api/coding/paas/v4/chat/completions, temperature 1, top_p 0.95, reasoning_effort max, thinking enabled with clear_thinking false, json_object, no streaming, 32768 output tokens, request timeout 600 seconds. At most one existing correction uses 1024 tokens, low effort, and the remaining original request deadline. The original system and correction prompts remain byte-identical.

Budgets are 8 tool proposals, 180 cumulative Runner seconds, 30 seconds per operation, 8192 history bytes, 4096 bytes per result, and 32768 aggregate result bytes. Each attempt starts from a separate clean baseline clone and a new Host session. No model history, candidate, failure feedback, or hidden-test result passes to another attempt.

The signed Launcher currently labels the provider GLM-5.3-Flash although the Host's request pins glm-5.3. Before each data decision the actual model, provider, endpoint, group, attempt ID and data categories must be explicitly disclosed in the authorization request. The trusted Launcher still makes its existing separate data and operation decisions. An unconfirmed target or data scope stops transmission.

Existing opt-in Host diagnostics are extended with three fixed events: action_response_received, action_text_normalized, action_response_accepted. They carry only initial/correction attribution. Normalization is recorded before field decoding; acceptance is recorded after existing semantic and wire validation. Therefore a normalization followed by rejection is not counted as normalization accepted. The observer bounds events to 128 (enough for nine turns with one correction each), flags overflow, drops unknown payload fields, and retains no raw model text, argv, paths, or workspace data. Sequential, exclusive product runs and process-bound log capture associate events with one attempt; synthetic preflight logs remain separate.

Per-attempt protocol metrics are initial responses/accepted/rejected, shape failures, missing text, normalizations applied/accepted, corrections requested/accepted/failed, and terminal error. Per-attempt coding metrics are proposals, approvals, executions, reads, writes, model test commands, source changes/diff, repairs, task terminal and independent grade. Missing or incomplete observation is NOT_CAPTURED; tool counts never substitute for model-response counts.

The unchanged grader runs in a separate fresh clone after product termination. Candidate bytes are copied through its existing path validation, candidate test edits are excluded, and original hidden tests are applied only to the grader clone. Coding PASS requires an actual authorized source edit committed through the existing Kernel path, complete grading with all hidden tests passing, no boundary violation, and complete terminal evidence. Otherwise use NO_CANDIDATE, FAILED, or NOT_GRADED, with INCOMPLETE evidence when appropriate.

Report denominators and every failure separately. Historical M8 attempts and deterministic probes are excluded from formal sample counts. Four attempts are exploratory and cannot prove general coding reliability. If any security anomaly occurs, stop the affected experiment and preserve evidence. Raw logs, candidate bytes and grader output stay in a local directory with owner-only permissions; GitHub receives reviewed bounded summaries and hashes.

This protocol must be frozen, A/C builds verified, deterministic and signed preflight passed, and current/exact-base Security Freeze passed before any formal remote call.
