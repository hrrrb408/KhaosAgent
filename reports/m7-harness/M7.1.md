## Before editing: observed lifecycle and failure

The production path is untrusted model/AgentHost → trusted Launcher → Kernel →
Seatbelt Runner. The Launcher owns its loop, approval, scope review, execution,
8 calls / 180 cumulative seconds / 30 seconds per command / 4 KiB per result /
32 KiB aggregate budgets. None is moved or expanded.

| Phase / event | Existing owner and state | Legal next event / terminal |
| --- | --- | --- |
| User request | Host rejects while `taskProgress.awaitingToolResult`; resets Host call accounting, pending proposal and task history when accepted | Generate one action; model failure returns an error |
| Request in progress | Host `handlingRequest` serializes the asynchronous XPC handler | Concurrent request gets nil; the flag clears when processing finishes |
| Model output | Adapter parses; Host validates action and existing protocol encodes/decodes it | Text ends task; a valid proposal becomes pending; invalid output gets at most one existing correction |
| Pending proposal | Host records one proposal, sets `awaitingToolResult` only after valid encoding | Launcher independently approves or refuses; Host state is no grant |
| Awaiting approval / execution | Launcher independently counts proposals, time and result bytes; Kernel enforces scope/OS isolation | One bounded result, with trusted `ok` and `can_continue` |
| Result accepted | Host requires a pending result, clears pending shell/evolution and `awaitingToolResult` before model continuation | If continuation allowed: text/list/shell; otherwise text only |
| Nonzero command result | Existing Host retains failed read-only argv until a result reports workspace changes | Exact repeated argv rejected; distinct proposal still requires approval |
| Refusal / Picker cancellation / execution stop / exhausted trusted budget | Launcher sets `can_continue=false` | Model cannot submit another tool action; final text or rejection error |
| Correction | Same context checks and same action encoder as initial generation | Valid action, or terminal fixed rejection code; no second correction |
| Final text / model or validation error | Launcher finishes current task; Host may accept a new user turn once no result is pending | Explicit new user request; no automatic re-execution |

`handlingRequest` is concurrency control, `awaitingToolResult` is sequencing,
and Host tool-call accounting is untrusted defensive accounting. The two task flags/counters are now held by the small `AgentHostTaskProgress` value; its three operations begin a task, record a proposal and consume a pending result. counters and Kernel enforcement remain authoritative. These observations are
source analysis; deterministic tests below cover the extracted action/context

## Change and reuse

The existing action validation/encoding moves within untrusted intelligence
files into `AgentHostActionOutput`; the initial and corrected outputs now call
one context validator. The existing trusted protocol encoder/decoder remains
the canonical bounded wire validator. No duplicate scope validator is added.
Existing gates now throw fixed, payload-free enum cases:

- Remote model JSON/object parsing, exact keys, field types retain their existing
  distinct provider error codes (`invalid_model_output_*`).
- Unsupported type, post-tool action, explicit Plugin intent, repeated failed
  command, nonempty unused text fields, Plugin fields/interface, evolution
  fields, workspace fields, and final wire contract rejection identify actual
  existing guard groups. `wire_contract` deliberately does not guess which
  trusted wire constraint failed (duplicates, byte bounds, reviewability, etc.).
- Local extraction/decoding retains `local_model_invalid_output`; it has no
  evidence to subdivide JSON/shape/type failures. Provider, timeout and context
  errors are not misclassified as action errors.

Semantic failures use the existing bounded error string field:
`invalid_agent_action_<category>[_after_correction]`. The suffix indicates that
the single correction was already consumed (including a preceding remote
format correction). No protocol version, field, IPC operation or trusted
consumer changes. All codes round-trip through the existing 64-byte limit.
Host stderr also emits only fixed category/attempt/terminal values. No raw
model response, path, argv, Plugin input or exception description is logged.
These are untrusted diagnostics, not approval or Kernel evidence.

The generic post-tool correction previously mentioned only shell even though
the actual contract allows list. It now describes text/list/shell and existing
single-line/unique-scope constraints. This repairs a demonstrated instruction /
contract mismatch; it does not establish the cause of older uncaptured outputs.
No new retry, permission inference, automatic approval or parameter guessing.
